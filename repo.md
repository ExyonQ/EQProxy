# EQProxy

Language: **English**.

Minimal-observability TCP/HTTP reverse proxy, written in safe Rust
(`#![forbid(unsafe_code)]`).

## Status — v0.5.0 «Operabilidad y confianza»: real HTTP/1.1 proxy (strict
framing including interim 1xx and `Expect: 100-continue`, per-phase
timeouts, signal cancellation) + TLS (termination, backend TLS verified by
default, ALPN h1, mTLS with client CAs), weighted round-robin with active
TCP/HTTP health checks (`expect status`/`expect rstring`) and passive
failure detection, safe connect-phase retries (idempotent-only unless
opted in) with bounded backend queues, incoming PROXY protocol v1 with
origin allowlists (plus v1 send), forwarded headers (XFF/X-Real-IP),
custom local responses, hot config + certificate reload under traffic with
measured swap latency, backend keep-alive pool (A16), the diagnostic CLI
(`explain` with per-timeout outcomes, `diff`/`plan`, offline
`apply`/`rollback`, `doctor`), framing fuzz corpus + live fuzz, first
benchmarks vs 3.4.6 (all comparable after the pool; see
[docs/evidence/phase2c/bench.md](docs/evidence/phase2c/bench.md)) and the
24h soak harness with published budgets (BENCHMARK_PLAN §9; the soak gate
itself is running on netcup-bench, results pending).
See [SPEC.md](SPEC.md) for the specified behaviour.

Docs language: from v0.3.0, documentation is published in English only.

## Build

```bash
cargo build --release --locked
```

Binary: `target/release/eqproxy`.

## Quick start

```bash
# Validate a configuration (errors with file, line, field, cause and example)
eqproxy config validate --config eqproxy.toml

# Start the dataplane
eqproxy run --config eqproxy.toml
```

Planned commands that today exit with explicit code 2 ("not implemented yet",
never simulated success): `config import` (reference proxy converter,
Phase 8). `config explain/diff/plan/apply/rollback` and `doctor` are
implemented (Phase 3); `apply`/`rollback` manage versioned state offline,
and `kill -HUP` hot-reloads the config under traffic (S-CFG-01, fail-closed
with a validated candidate gate).

The canonical format is documented in
[docs/adr/0002-configuration-format.md](docs/adr/0002-configuration-format.md);
the full example lives in [eqproxy.toml.example](eqproxy.toml.example).

## Known limitations (documented, not hidden)

### cargo-geiger: incomplete `unsafe` inventory (INCONCLUSIVE)

`cargo geiger` finishes with `error: Found N warnings` because it cannot reach
some dependency files. **This is not a pass** (Veyra Proof criterion). Root
causes, all upstream of cargo-geiger (tested on 0.13.0, 0.14.0 and git main
`#118a9a28`; pinning `signal-hook-registry` to 1.4.7 fails the same way):

1. Its parser (syn) does not accept `signal-hook-registry`'s syntax
   ([cargo-geiger#240](https://github.com/geiger-rs/cargo-geiger/issues/240)).
2. It reports as "never scanned" files that rustc lists in dep-info but that
   are not scannable: markdown included with `include_str!` (clap) and
   `private.rs` files generated by build scripts and `include!`-ed
   (serde/serde_core/thiserror)
   ([#145](https://github.com/geiger-rs/cargo-geiger/issues/145),
   [#577](https://github.com/geiger-rs/cargo-geiger/issues/577)).

**Manually verified compensation** (the exact inventory gap):

| Unscanned file | `unsafe` constructions |
|---|---|
| `signal-hook-registry-1.4.8/src/lib.rs` | 30 (tokio unix signal FFI) |
| `errno-0.3.14/src/unix.rs` | 4 |
| `errno-0.3.14/src/lib.rs` | 0 |
| generated `private.rs` (serde, serde_core, thiserror) | 0 |
| clap markdown (not code) | — |

The workspace's own `unsafe` remains forbidden by `#![forbid(unsafe_code)]`;
the gap is in the signal FFI of dependencies, inventoried above.

### Miri: 22 tests not run (20 impossible + 2 too costly)

Miri **does not emulate networking or processes**
([rust-lang/miri#3449](https://github.com/rust-lang/miri/issues/3449), Miri
README): the 14 socket e2e tests and the 6 process tests are impossible under
any flag. 2 more tests (accepting an exact 1 MiB config) are excluded because
of measured cost: >8 min of interpreted parsing per test, with the boundary
covered by the regular suite and CI. Everything else runs under miri, including
4 tokio-runtime tests rewritten to use a runtime without an IO driver
(mio/kqueue is unemulated FFI on macOS,
[#4007](https://github.com/rust-lang/miri/issues/4007)).
